## For the team — what actually shipped

### 3.2a · Archive→Postgres ingest driver (PR #23)
The archive existed in the `source_documents` table; the parsed JDs did not. Built the ingest driver to populate `parsed_jds`:
- Postgres `source_documents` (raw files) → regex parser → `parsed_jds` (sections + metadata).
- **Fixed two defects exposed during the build:** (1) the parse was non-idempotent — re-running a batch without clear could corrupt the result; (2) incumbent names (which SFU's JDs use idiomatically — *"Reporting to the Vice-President…"*) would have crossed the network to the Ollama host on `aria-gb10-2`. That is a FIPPA question; we normalize them out at the rule level instead. Idempotent + safe.

### 3.2b · Embedding service (PR #24)
Postgres `parsed_jds` → `nomic-embed-text` on `aria-gb10-2` → Neo4j 768-dim vector index (cosine distance).
- **Document-level embeddings + section-level embeddings** — both indexed for retrieval.
- **Every embedding default was measured, not guessed:**
  - `max_chars=10000` — serialized JDs max at 8,987 characters; the value is conservative and data-driven.
  - `cosine_confirm` OFF — the LSH confirmation layer (Tier-3) does its own cosine work; the vector index does not need to redundantly confirm.
  - Batch size: serialized to control memory and latency.
- **Idempotent, content-keyed, and reconciling** — can re-embed without side effects; tracks state in `embedding_runs`.

### 3.3 · Tier-2 near-duplicate detection (PR #27)
MinHash/LSH over word-5-gram shingles → exact-Jaccard confirmation → `DedupEdge(tier=NEAR_DUPLICATE)`.
- **Two key findings overturned the plan:**
  - **Document cosine is useless here.** 98% of JDs have a neighbour ≥ 0.92 cosine similarity. Cosine bar does not filter; it confirms everything.
  - **The "same position_id = duplicate" oracle is worse than none.** Negatives are more similar than positives. **SFU's redundancy is cross-position cloning, not within-position revision** — 798 of 1,037 duplicate groups (77%) span more than one position ID. These are distinct positions sharing a byte-identical JD; Tier-1 handed clustering a 1.0-similarity cluster for free.

### Two extraction defects (the headline of this period)

**Defect 1 — docx tables & content controls (PRs #30/#31):**
- `_extract_docx` read only `<w:p>` (body paragraphs) and silently skipped `<w:tbl>` (tables) and content controls.
- **~20.7M characters lost across 2,596 files; 24 files extracted to nothing.**
- Fixed. Rescued **3,278 files from broken parse** (docx + content controls).

**Defect 2 — the WJQ template parser (PRs #32/#33):**
- SFU's Weighted Job Questionnaire is ~**4,300 files (29.5% of the archive)** — a structured form with 14 labelled sections (Duties, Knowledge, Skills, etc.).
- The segmenter couldn't read it; it chewed up the form as one undifferentiated block.
- **New marker-routed parser** reads the template; duty frequency `(D)/(W)/(M)/(S)` → `SFUDuty.frequency` field.
- **WJQ is parse-only and EXCLUDED from the HR approval bar.** It is CUPE; the bar is JDFN-only. The rulebook defines no WJQ scoring gates. Scoring CUPE work under the JDFN approval bar is a category error. **Deferred to HR** (registered as HR-143).

### Pipeline state (refreshed end-to-end)
- **Archive:** 9,517 → **14,395** documents with vectors; **99.3% parseable** (105 broken: all WJQ, excluded from the bar).
- **Vectors:** 22,922 → **36,174** section-level embeddings in Neo4j.
- **Dedup:** 14,312 → **15,072** near-dup edges (Tier-2). Archive **~99.4% covered end-to-end** (parse → embed → dedup).
