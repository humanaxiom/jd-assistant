## For HR — the one thing that matters

**Nothing about the approval bar changed, and the archive's own numbers are now on screen unaltered.**
The dashboards *display* the Phase-2.5 baseline (the 874-JD current-practice cohort at 78.6%) straight
from the committed artifact — they compute nothing and change no threshold. The whole-archive rate is
shown but demoted with its "category error — never quote" warning, exactly as the baseline README frames
it. The review queue is the same human-approval spine (4.4b): a canonical stays a DRAFT until a reviewer
approves, and the system refuses to publish unless the gates already permit it.

**And the local-only guarantee is now enforced, not asserted.** "Local" was ratified to mean *not
cloud / not third-party* — JD text may cross the private network to internal infra we control
(`aria-gb10-2`), never to a vendor. The build now **fails** if either content client is pointed at a
non-internal host.

## For the team — what actually shipped

### Read-only dashboards (baseline · dedup · clusters)
Server-rendered Jinja pages *inside* the FastAPI `api` service (the same test-gated surface as the 4.4d
review UI — no JS build, no new runtime dependency). Each page loads a committed report artifact
(`docs/baseline/summary.json`, `docs/dedup/*.json`, `docs/cluster/cluster-summary.json`) and renders it,
reusing the existing `extra="forbid"` report models — **verified in-container that each REAL artifact
validates** (guards against the silent-empty-state drift trap). Graceful empty-states on missing/corrupt
artifacts (HTTP 200, never 500), including per-tier degrade on the dedup page. The baseline aggregator
gained one change: it now emits the **874-JD current-practice cohort** as its own segment
(`SegmentDimension += "cohort"`) so *the* headline number lives in the committed artifact instead of an
uncommitted working file. Every headline figure is pinned to a distinct sentinel fixture — hardcoding
one goes red (mutation-verified by the reviewer on all three pages).

### Egress guard — NN #5 is now build-enforced
New `core/src/jd_bank/security/egress.py`: `assert_inference_host_allowed(base_url)` raises
`DisallowedInferenceHostError` for any host not on `settings.allowed_inference_hosts` (default
`aria-gb10-2` + loopback/private; env-overridable via `ALLOWED_INFERENCE_HOSTS`). Both JD-content
network sinks (the rewrite/audit LLM client and the embeddings client) call it **before** constructing
their `AsyncOpenAI` client, so JD text cannot leave for a cloud/third-party host. Stdlib only, no new
dependency. The Opus security review verified fail-closed by mutation (deleting the guard from either
client turns its pin red) and rejected every bypass attempt (userinfo tricks like
`aria-gb10-2@api.openai.com`, `127.0.0.1.evil.com`, encoded IPs, case, trailing-dot, public IPv6).
`docs/security/egress-audit.md` enumerates every network sink and confirms the harness's own
memory/agent clients carry lineage/code, **not** JD archive content.

### Review queue seeded — the spine, demonstrated on real data
`make canonical-drafts CANONICAL_ARGS="--no-llm --limit 5000"` persisted **379 DRAFT canonical_jds**
(378 multi-member role clusters + 1 singleton; 751 clusters recomputed from the 133,842 role-equiv edges
over the first 5,000 parsed JDs), each with an append-only audit-log row. The live review UI is now
populated end to end: queue → detail (draft + score + SFU gates) → approve/reject/edit/override. These
are the **deterministic 4.1 merge** drafts (`--no-llm`, zero egress) — the 4.2 LLM rewrite/audit
(`gpt-oss:120b` on `aria-gb10-2`, now guard-permitted) can refresh them in place. `--limit` bounds
*input* rows, not output drafts.
