# Shipped — 2026-08-14 · Security, the review experience, and CUPE

The one-pager for catching up. **This entry covers three weeks** — the series stopped at
2026-07-24 while the work did not, and a status log with a three-week hole is one nobody
trusts the next time they read it. It is written from `git log origin/main` and the merged
PR numbers, not from memory.

Three things happened since Phase 5: the system was made **safe to deploy**, the **reviewer's
experience** was finished, and **CUPE** — a third of the archive — stopped being a category
error.

## 1. Security and deployment (P0.0 – P0.4, #82 – #92)

The 2026-08-07 architecture review found that **the JSON API was an unauthenticated publish
endpoint** (#82). Everything in this block follows from that.

- **Authentication and authorization on every route** (#82), CSRF protection on every
  cookie-authenticated state change (#85), and the CAS round trip bound to the browser that
  started it with `next` pinned to this app (#91, #92).
- **A production posture that refuses to run unsafely** (#83, #90) — and it was **proven by
  deploying it**, which is how three defects were found that reading had not: P0.2's guard
  reached zero of fourteen containers, a Neo4j setting was mistyped, and a healthcheck read a
  variable that does not exist inside its own container.
- **Deployment origins** (#89): a CAS origin allowlist, and the data stores moved off
  `0.0.0.0` onto `127.0.0.1`.
- **Navigability** (#88): a front door, error pages written for people, and a link crawl that
  proves every same-page link resolves.

### 🔴 Still open, and it is not a repo deliverable

The pilot host `sfuai.ca:7000` is **internet-facing over plain http**, so session cookies and
CAS tickets cross the open internet in the clear. The app is correct *behind* a TLS
terminator and refuses to pretend otherwise — **someone has to put one in front of it.** That
is a deployment decision nothing in this repository can make.

## 2. The review experience is complete (Phase 8, #94 – #106)

- **The HR ask is 65 settings, not 197** (#94). The decision register is tiered, so what HR
  must actually sign is separated from engineering settings, and the generated register leads
  with *"Your decisions"*.
- **The reviewer can see how a draft was assembled** (#95) — and the backlog item understated
  the defect: `merge_provenance` had been computed and persisted since Phase 4.1 and was read
  by **nothing**.
- **A word-level diff** between versions (#102), **a structural sidebar** showing the roles
  clustering *refused* to merge (#105), and **jump-links from a blocking gate to the field it
  is about** (#106).
- **Runbooks for backup/restore and reindex** (#108), each **executed against the live stack
  before being written down** — which is how we found that `pg_restore --data-only` into an
  already-migrated database **silently destroys the Bank and exits 0**.

## 3. CUPE — the third of the archive we had never built for (#109 – #113)

**Why CUPE was singled out when APSA is the same size** (4,946 APSA vs 4,440 CUPE): it is not
that CUPE is unusual. **CUPE uses a different FORM.** APSA/APEX/POLY are the **JDFN**
template, which the validator, the gates, the thresholds and the Builder were all written
against. CUPE 3338 uses the **WJQ**, a 14-section point-factor questionnaire. It got a parser
in Phase 3.4 and nothing since.

Measured through the shipped validator, **0 of 600 CUPE JDs were approvable** against a bar
built for a form they were not written on. Four rules fired on **100%** of them — because the
WJQ does not contain the sections those rules check.

| Phase | What it did | |
|---|---|---|
| **A** | 81.4% of CUPE JDs were stored **truncated** — `additional_context` had inherited the position-summary character cap while the parser called the result *"verbatim — lossless"*. Whole archive re-parsed; **now 0%**. | #109 |
| **B** | **Every rule declares which form it can judge** (`applies_to`, required with no default). CUPE mean 51.4 → **62.9**; JDFN **identical**, which is the half that matters. | #110 |
| **C** | **The numbers are per-form too.** `duties_max` is **12** for the WJQ — the form has twelve duty slots and 77.4% of CUPE JDs fill all twelve. | #112 |
| **D** | **The Bank drafts CUPE roles.** 657 clusters (26.7%) had been skipped entirely. Also fixed the rewrite prompt, which asked *every* draft for JDFN's 3–5 duties and would have deleted most of a CUPE role. | #113 |

**What CUPE still needs from HR** is scope (HR-194: may the *Builder author* CUPE?) and
HR-201 (do SFU's boilerplate requirements apply to a form that has no such block?). Neither
blocks the work above.
